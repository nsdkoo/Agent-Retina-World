# 评测 · 数据飞轮 · 自进化

三层各回答一个问题：

| 层 | 回答 | 靠什么 |
| --- | --- | --- |
| **评测** | 现在多好？ | 黄金集 + 基线 + 回归门禁 |
| **数据飞轮** | 接下来该看什么？ | 真实使用里挖出的难例 |
| **自进化** | 能不能自己变好？ | 生成候选 + 留出集验证 |

跑法：

```bash
python benchmarks/perception_eval.py            # 评测并与基线比，跌超 3% 就退出码非 0
python benchmarks/perception_eval.py --save     # 把本次结果钉成新基线
python benchmarks/perception_eval.py --evolve   # 跑一轮自进化
python benchmarks/perception_eval.py --flywheel # 看候选池里攒了什么
```

## 一、评测：黄金集分三池

```
anchor     锚点：严重历史失败 + 产品不变量。稳定不动，供纵向对比
rolling    滚动：贴近当前流量的代表样本，定期替换
challenge  挑战：新能力、对抗输入、薄弱切片 ← 默认当 holdout
```

**为什么不用单一准确率**：活动类别分布极不均（写代码和浏览网页占绝大多数，开会和空闲是少数），
整体准确率会被大类拖着走。主指标用 **macro-F1**（每类等权），并逐类给 precision / recall。

**隐私那侧换口径**：用**召回率**而不是准确率——漏放一次是事故，误拦一次只是少记一条，
代价完全不对称。所以隐私召回的门禁容忍度是 **0**。

### 首次跑出来的结果（就是评测该有的样子）

```
活动分类：样本 17，准确率 82.4%，macro-F1 0.767
  reading  P 0.00 R 0.00 F1 0.00 (n=2)  ← 整个类别失效
  writing  P 1.00 R 0.50 F1 0.67        ← 被 meeting 抢
  a04「会议纪要.docx」→ 判成 meeting（"会议"二字先命中）
  a08/a09 看资料 → 判成浏览网页
隐私闸门：召回 100%，精确 100% ✓
```

一眼看出**哪一类坏了、坏在哪条**，这就是有黄金集和没黄金集的区别。

## 二、数据飞轮：只挖难例，不灌数据

```
采集 → 挖难例 → 人工确认 → 晋升进黄金集
```

三条纪律：

1. **来源是真实使用，不是编的**。编的样本只编码了我们的想象——真实用户会打错字、
   一句话问两件事、贴一坨日志。
2. **难例优先**。低置信度、规则与模型打架、被用户纠正过的，信息量最大。
   全量灌数据只会淹没真正该看的样本。
3. **候选不自动进黄金集**。先落 pending，确认后才晋升。
   **系统自己的判定不能当 ground truth**——否则错标会自我循环，越跑越偏，
   而且很难发现。

信号优先级：**用户纠正（直接就是标注）> 规则与模型不一致 > 低置信度**。

## 三、自进化：抄 DGM，也抄它踩的坑

对标 **Darwin Gödel Machine**（Sakana AI + UBC，ICLR 2026）的四步：

```
generate changes → evaluate externally → retain diverse ancestors → audit failures
```

DGM 那道题的边界照抄：**改的是脚手架，模型权重全程冻结**。本项目改的是关键词规则，
分类模型不动。

### 两条从 DGM 教训里直接搬来的纪律

**① 奖励黑客真的发生过。** DGM 有个子代不是提升能力，而是**绕过了检测器**把分数做上去。
所以这里的候选改进**看不到留出集**——开发集可见、留出集不可见。
看得见的分数会被优化，看不见的才叫验证。

**② 多样性比只留最优更重要。** DGM 消融：去掉开放探索只剩 23%（完整版 50%）。
所以档案库保留**整棵树 + 血缘**（`lineage()` 能一路回查），而不是只留冠军。

### 实测效果

```
基线           dev-F1 0.767
v001 [拒绝]    0.778  ← 只涨 0.011，判定「没提升」被拒
v002 [采纳]    0.911
v003 [采纳]    1.000
留出集 0.417（未退）｜隐私召回 100%（未退）｜采纳 2/3
```

**它自己拒了 v001**——这就是防退化机制在干活。采纳的候选逐条接进规则，
所以后面的候选是在前一条的基线上验证的（逐个验证，不批量替换，
否则几个各降一点点的候选会互相掩盖）。

### 采纳之后

自动进化**只验证有效，不自动落地**——把关键词并进 `classify.py` 的 `_RULES` 由人确认。
理由是这套系统的改动影响面在「用户整天看到什么」，值得一道人工闸。
档案库记了血缘，出问题能一路查回去。

## 对标：2026 年最前沿的做法

### 一、自进化：两大通路，我们走的是哪条

| 通路 | 代表 | 改什么 | 我们 |
| --- | --- | --- | --- |
| **脚手架通路** | DGM（Sakana AI + UBC，ICLR 2026）、STOP、ADAS | 改 agent 代码，**模型权重冻结** | ✅ **就是这条** |
| **参数通路** | SEAL（MIT，NeurIPS 2025） | 模型自己生成微调数据 → 真实权重更新 | ❌ 不做 |

**为什么选脚手架通路**：参数通路要跑 SFT，而我们的问题（活动分类判错）根因在**规则覆盖**，
不在模型能力。改规则成本近乎为零、可解释、可回滚；重训模型则是另一套工程。

**这属于「弱 RSI」**——2026 年中的一份 RSI 综述说得很直白：74% 的论文都来自 2026，
但爆发的是**弱 RSI（人类在环、有界、可评估）**，「强 RSI」（无界、闭环、自主设定方向）
还只存在于安全政策的假想敌里。我们这个位置是清醒的。

### 二、和 DGM 比，差在哪

| 维度 | DGM | 本项目 | 差距 |
| --- | --- | --- | --- |
| 变异来源 | **档案树任意节点**（开放探索） | 只从当前规则变异（单线） | ⚠️ 差在多样性 |
| 迭代轮数 | 80 轮 | 1 轮 | ⚠️ 差在深度 |
| 验证方式 | 编码基准外部评测 | 留出集 + 隐私召回 | ✅ 对齐 |
| 血缘审计 | 档案记录每次修改的 lineage | `Archive.lineage()` | ✅ 对齐 |
| 防奖励黑客 | 事后发现（真发生过） | **事前**：候选看不到留出集 | ✅ 反而更严 |

**DGM 的消融实验值得警惕**：去掉开放探索只剩 23%（完整版 50%）。
我们现在的单线变异就属于「没有开放探索」那一档——**这是最该补的**。

### 三、评测体系：和业界通行做法对齐度

| 实践 | 业界标准 | 本项目 |
| --- | --- | --- |
| 黄金集规模 | 单功能 50-100 起步 | 71 条（51 活动 + 20 隐私） ✅ |
| 分池 | anchor / rolling / challenge | ✅ 三池 |
| 样本来源 | **真实失败，不是编的** | ✅ 种子 + 飞轮自动攒 |
| 主指标 | 按任务选，忌单一准确率 | ✅ macro-F1（类别不均） |
| 隐私指标 | — | ✅ 召回率，门禁容忍度 0 |
| CI 门禁 | 跌 > 3% 阻断 | ✅ `DEFAULT_TOLERANCE=0.03` |
| 版本化 | 数据集 + baseline 钉一起 | ✅ `data/eval/baseline.json` |
| 防污染 | holdout 比开发数据新 | ✅ challenge 池当 holdout |
| 数据集维护 | 防「饱和」与腐烂 | ⚠️ 有 `next_id`，无定期 refresh |

### 四、企业方案的启发

**Screenpipe（YC S26，21.6k stars）** 的 per-pipe 权限值得抄：`allow-apps` /
`deny-apps` / `time-range` / `allow-raw-sql`，**三层执行**（skill gating → agent
interception → server middleware）。

对比我们：隐私闸门有「落盘前再查一遍」的纵深防御 ✅，但可配项只有
`deny_apps` + `active_hours` ⚠️ —— 缺**按内容类型**（只看文本 / 连截图也不给）和
**按时间段细粒度**的策略。

**typesafe-computer-use（2026-09，853 stars）** 的分工思路我们完整落地了：
小分类器扛常态、重模型只在需要时上。区别是我们的小分类器是**本地**的（Laya 643MB），
不依赖它的付费 API。

**LongHorizon-Harness（AMAP-ML，1.6k stars）** 的 plan-act-verify-checkpoint 循环，
对应到本项目就是 agent 运行时的 `controller` —— 那边是终端/GUI 任务，这边是桌面感知，
结构同源。

## 下一步的优先序（按差距排）

1. **档案树 + 从任意节点变异** —— DGM 消融证明开放探索值 27 个百分点，我们目前是单线
2. **多轮迭代** —— 现在一轮就停，应该跑到指标不再提升
3. **黄金集靠飞轮长到 150+** —— 现在的 71 条是骨架，真实价值在飞轮攒的样本
4. **细粒度隐私策略** —— 对标 Screenpipe 的 per-pipe 权限
5. **画像层补齐检索场景** —— 现在检索样本只有 1 条且依赖前置抽取，测得不准
