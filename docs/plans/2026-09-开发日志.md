#### 这一段挖出的三个 P0 bug（都值得记）

三个 bug 有**共同特征：指标恒为满分**，所以长期没被发现。

1. **隐私评测恒真** —— `runner.py` 与 `loop.py` 里 `expected` 和 `predicted`
   赋了同一个值，导致漏放数永远是 0、**隐私召回永远 1.0**。
   那条「漏放即事故、容忍度 0」的门禁**从来没生效过**。
   修完用「故意全放行的假闸门」反向验证：召回必须掉到 0 才算真的在算。

2. **飞轮节流是丢弃式的** —— 30 秒内的其他难例直接丢，且不可观测。
   `data/eval/` 下从来没有 `flywheel.json`，说明飞轮压根没跑起来过。

3. **画像层「检索」是假的** —— `_trial_retrieve` 是个桩，
   实际测的是抽取。检索能力一天都没被测过。

**后来的印证**：黄金集从 71 扩到 153 之后，隐私召回**从「100%」掉到 78.8%**
（NordPass Vault / 云闪付 / accesskey / 护照 / 病历全拦不住）。
再次说明 —— **样本不全会制造虚假的绿色信号**。

### 09-30 · 差异化第一步：记忆接进决策

- **做了什么**：`Planner` 加 `context_fn`，规划时会参考「这件事用户平时怎么干的」；
  episode 摘要带上用过的工具名与动到的路径。
- **为什么**：审计发现 **`agent/` 目录零引用 `memory`** ——
  三层记忆齐备却只服务 chat 路径，agent 干活时一次都不看，等于「只写不读」。
  这是把「陌生人」变成「熟人」的第一步：**传统桌面 agent 的天花板不是看不准屏幕，
  而是每次都像陌生人第一次来你家**。
- **取舍**：只做收尾回流 + 规划前注入，**不做**「让 agent 自己决定记什么」——
  那会把记忆变成不可控的黑盒。
- **涉及**：`agent/planner.py`、`memory/assembler.py`、`agent/controller.py`
- **commit**：`45f9928`
